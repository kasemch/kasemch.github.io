# Phase 2 — Google Calendar Integration Architecture v1.0

Status: PHASE 2A + 2B IMPLEMENTED ON DEVELOPMENT BRANCH / 2C DEFERRED

## Objective
Connect the approved Compact Academic Calendar to Google Calendar while preserving the public/private boundary of the GitHub Pages site.

## Source of Truth
Google Calendar is the calendar source of truth. GitHub Pages remains a static presentation layer only.

## Security Boundary
- No client-side storage of refresh tokens, client secrets, service-account keys, or write-capable long-lived credentials.
- Public pages may display only events explicitly approved for public visibility.
- Private events, teaching schedules, meetings, deadlines, and personal items must not be emitted into the public Jekyll build.
- Write operations require authenticated user action and an external trusted integration layer.

## Phase 2A — Read Architecture
Implemented with `_data/public_calendar.yml` as the fail-closed public projection.

Rules:
1. Calendar/category mapping remains canonical in site data.
2. Only records with `visibility: public` are rendered by the public component.
3. The JavaScript month renderer receives only projected public dates from rendered HTML.
4. No Google credentials, attendee lists, private meeting links, or restricted notes belong in the public projection.
5. The projection can later be generated by a trusted integration process without changing the public UI contract.

## Phase 2B — Add Event Flow
Implemented as a review-before-save workflow requiring no write-capable credential.

Flow:
User -> Static form -> Client-side validation -> Google Calendar template URL -> User review -> User saves in Google Calendar

The event builder fixes authored-event timezone handling to `Asia/Bangkok` and verifies that end time is later than start time. The GitHub Pages site does not store submitted form data.

## Phase 2C — Authenticated Direct Write (deferred gate)
Direct `events.insert` remains deferred until an authenticated external integration layer is selected and reviewed. The static site must never embed write-capable secrets.

Required before Phase 2C:
- external trusted integration provider selected;
- OAuth consent and redirect model reviewed;
- minimal Google Calendar scopes established;
- token storage kept outside GitHub Pages;
- explicit user authorization and revocation flow defined;
- private/public event projection tested fail-closed.
